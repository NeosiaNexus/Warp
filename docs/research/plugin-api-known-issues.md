# Défauts connus des API plugin des proxys concurrents (Velocity, BungeeCord, Waterfall, Gate)

Recherche du 2026-11-02 pour la conception de l'API plugin de Warp. Aucune ligne de code.

## Méthode et lecture

- **Sources** : issues, PR et fils de discussion GitHub de `PaperMC/Velocity` (principal), `SpigotMC/BungeeCord`, `PaperMC/Waterfall` (archivé), `minekube/gate`, `LuckPerms/LuckPerms`, plus la lecture du code actuel de `VelocityConnectionListener` et `AbstractConnectionListener` de LuckPerms.
- **Procédure** : export complet des titres (925 issues et 977 PR Velocity, 2707 issues BungeeCord, 641 Waterfall, 175 Gate), filtrage par mots-clés, recherche plein texte ciblée, puis lecture des fils (corps et commentaires). Environ 350 fils récupérés, environ 230 lus en détail.
- **Qui parle** : astei (fondateur de Velocity), electronicboy, kezz, Strokkur424, mbax (membres PaperMC), 4drian3d, Xernium, Gerrygames, hugmanrique, A248 (contributeurs Velocity), WouterGritter (membre de l'org mais se décrit lui-même comme "not a maintainer with any rights", V#1816), md-5 (BungeeCord), Janmm14 (contributeur BungeeCord, pas mainteneur), Outfluencer (collaborateur BungeeCord), robinbraemer (Gate), lucko et emilyy-dev (LuckPerms). Les citations sont courtes et en langue originale.
- **Notation** : `V#n` = Velocity, `B#n` = BungeeCord, `W#n` = Waterfall, `G#n` = Gate, `LP#n` = LuckPerms. État au 2026-11-02 avec l'année d'ouverture. "(titre seul)" signale une ligne fondée uniquement sur le titre.
- **Limite** : les fils ne disent pas toujours ce qu'on attendrait ; quand une issue a été close sans conclusion, c'est indiqué tel quel.

## 0. Synthèse : huit causes racines qui reviennent partout

1. **Aucun modèle explicite du cycle de vie d'une connexion.** Les événements sont attachés à des points du code réseau, pas à des états contractuels. L'arrivée de la phase CONFIGURATION (1.20.2) a cassé d'un coup des API "stables" sur les deux proxys : B#3519, B#3542, B#3525, V#1102, V#1117, V#1164, V#1368, V#1529. md-5 : "it is impossible for 1.20.1 and 1.20.2 to have the same behaviour" (B#3542).
2. **L'identité est l'UUID, pas la session.** D'où les courses Login/Disconnect pour un même joueur, jamais corrigées en 7 ans sur les trois proxys Java : V#1013, V#1691, V#439, V#1727, V#1740, B#2815, W#604. Le plugin le plus installé (LuckPerms) contourne en retardant le déchargement des données via un "housekeeper".
3. **L'asynchronisme a été greffé après coup.** Ordre indéfini dès qu'un handler est async (V#1560, B#1491, B#1858), handlers jamais terminés sans délai ni attribution (B#1858, LP#3713), suspension qui fait expirer le client (V#1367).
4. **Des opérations échouent en silence.** `ChatEvent#setMessage` sans effet (B#3336), méthodes `Audience` no-op (V#634), callbacks de resource pack jamais appelées depuis 2024 (V#1369), `sendPluginMessage` ignoré sans joueur (V#702), résultat `handled()` qui laisse le backend attendre indéfiniment (V#1453).
5. **Événements sémantiquement surchargés.** `DisconnectEvent` couvre toute fermeture y compris les connexions refusées (V#1691), `ServerKickEvent` de Waterfall couvre aussi la déconnexion du client (W#419), `ServerSwitchEvent` est aussi tiré au premier join (B#2816).
6. **L'API expose de l'état vivant ou des classes concrètes.** `getServers()` renvoie une map mutable non thread-safe (B#4005), la config vivante sert d'API (W#342), les événements sont des classes concrètes ("a very bad idea", astei V#378), le même objet `PendingConnection` est réutilisé à travers les phases avec des getters qui renvoient null (B#1918, B#3680).
7. **Aucun niveau bas sanctionné.** Faute d'API paquet, les plugins injectent dans le pipeline par réflexion (V#594, B#3545, V#1706). Quand l'API manque, la réponse officielle est "That method is not API" (md-5, B#3519), et le développeur demande "What should I do if there is no API?".
8. **Versionnage et dépendances tierces dans l'API.** Adventure 5 livré dans une version mineure (V#1842), conflit de versions Adventure transitives (V#401), aucune promesse de compatibilité dans les snapshots (V#1884), dépréciation impossible à éviter (PR V#1491).

## 11. Les 25 exigences de conception prioritaires pour Warp

Classement par impact sur la justesse des plugins et par coût de correction après la v1 (les premières sont impossibles à corriger plus tard sans rupture).

1. **Contrat de session.** Un objet `Player` n'existe qu'une fois le login validé. Tout `SessionStarted` reçoit exactement un `SessionEnded` (cause en enum fermée, dernier serveur atteint). Les connexions qui n'ont jamais été une session ne reçoivent qu'un `ConnectionClosed` bas niveau. (V#1691, V#1740, V#1696, V#289, B#1630)
2. **Ordre garanti par identité.** Pour un UUID donné, le début de la nouvelle session n'est tiré qu'après la fin complète de la précédente (handlers compris, délai borné) ; ressources réseau libérées immédiatement, seul le slot d'identité attend. Plus un `sessionId` UUID sur tous les objets et événements, partagé avec les connexions backend. (V#1013, V#439, V#1727, B#2815, W#604, V#1839, code LuckPerms)
3. **Livraison ordonnée par session.** Les événements dérivés de paquets d'un même joueur sont traités dans l'ordre d'arrivée ; une suspension arrête la chaîne de cet événement et les priorités suivantes attendent. Aucun handler ne change le thread des autres. (V#1560, B#1491, B#1858, V#756, PR V#1782)
4. **Suspensions bornées et attribuées.** Délai par type d'événement, chien de garde qui nomme plugin et méthode, reprise forcée avec résultat par défaut documenté, keepalives entretenus par le proxy pendant l'attente, annulation propagée si la connexion ferme. Exceptions isolées et attribuées ; aucune future qui avale une erreur. (LP#3713, V#1367, G#358, V#374, V#859)
5. **Machine d'états de connexion publique.** Phases HANDSHAKE, STATUS, LOGIN, CONFIGURATION, PLAY exposées ; chaque méthode qui émet un paquet déclare ses phases valides et met en file ou échoue explicitement ; diagramme officiel par version. (V#71, B#3519, B#3542, B#3525, V#1102)
6. **Phase de configuration de première classe.** Événements entrée/sortie à chaque (re)configuration, premier join compris ; tâches de configuration enregistrables (resource packs, dialogues, cookies, login queries) qui retiennent la phase ; événement "joueur prêt" (monde chargé). (V#1164, V#1832, V#1368, V#1117, B#3869, V#1541, V#570)
7. **Changement de serveur sans état ambigu.** `currentServer` jamais null pendant un changement, `pendingServer` séparé, `previous` et `isInitialJoin` explicites sur un jeu d'événements unique ; messages en transit mis en file, jamais jetés ; fermeture de l'ancienne connexion = étape garantie. (V#569, V#633, G#539, W#686, PR V#1309, V#1766, V#1545)
8. **Un seul événement de perte de backend.** Cause (kick, connexion perdue, timeout, échec de configuration, échec initial), résultat (rediriger, déconnecter avec message modifiable, notifier), garde anti-boucle ; jamais tiré quand c'est le client qui part ; raison backend conservée. (B#3695, W#419, W#758, B#3183, W#675, V#1018, V#1410, V#997)
9. **Requête de connexion à résultat scellé** (succès, déjà connecté, en cours, refusé avec raison, erreur), une seule variante ; choix du serveur initial à résultat et suspendable. (V#535, V#859, PR V#1787, B#3026)
10. **Canaux de plugin possédés.** Enregistrement avec direction, gestionnaire exclusif par canal, aucun relais automatique d'un canal possédé, messages client sur un canal "backend uniquement" jetés par défaut, source scellée, résultat d'envoi explicite, entrées client invalides jamais fatales. (B#3191, B#2545, PR B#3802, V#1560, V#1550, V#702)
11. **Chat et commandes signés honnêtes.** Résultats d'événement typés selon ce qui est faisable pour ce paquet ; aucune méthode silencieusement inopérante ; collisions de commandes signables détectées à l'enregistrement ; file unique ordonnée par joueur pour chat et commandes (limitation de débit comprise) ; état de la session de chat exposé. (V#866, V#1007, B#3336, B#3327, B#3486, V#1635)
12. **Arrêt en étapes contractuelles** : refus des connexions, pré-arrêt avec joueurs, fin de session garantie, arrêt des plugins, fermeture scheduler et bus ; délais configurables et lisibles. (V#322, PR V#1626, V#289, V#177, B#1718, LP#2415)
13. **Registre de serveurs dynamique et sûr** : instantanés immuables, événements, politique de désenregistrement, forwarding et handshake par serveur, cible de connexion utilisable sans enregistrement. (V#566, B#4005, PR V#1386, G#537, V#304, PR V#916)
14. **Miroirs d'état client resynchronisés** à chaque reconfiguration (boss bars, tab list, équipes, packs, header/footer) ; tab list en upsert à champs optionnels ; API équipes/objectifs ; le miroir n'expulse jamais pour une incohérence backend. (V#1529, V#1315, V#1455, V#605, W#318, B#2700)
15. **Zéro no-op silencieux.** Toute méthode exposée (y compris héritée d'Adventure) est implémentée ou absente ; tout résultat "géré" répond au pair. Tests de contrat automatiques. (V#634, V#1369, PR V#1453, B#3336, B#3499)
16. **Événements en interfaces ou records scellés**, implémentation interne, un seul modèle de résultat, sémantique de suspension fixée à la naissance du type. (V#378, B#1858)
17. **Priorités** : entier avec constantes nommées et sens porté par le type, départage déterministe, ordre surchargeable par l'administrateur ; enregistrement programmatique ; handler annoté invalide = erreur à l'enregistrement. (V#1536, PR V#1491, V#271, B#2023, B#1478, B#3004, V#1343)
18. **Chargement des plugins robuste** : doublons isolés, ordre contractuel avec `loadBefore/After`, `provides`, manifeste validé, un `ModuleLayer` par plugin, bibliothèques dédoublonnées contre les dépendances, bibliothèques fournies utilisables avec le loader du plugin, `ownerOf(Class)`. (V#955, V#1354, B#381, B#3139, V#1666, V#354, V#601, PR V#1853)
19. **Politique de compatibilité écrite** : semver sur les releases, liste des types tiers faisant partie du contrat, `@since` contrôlé en CI, toute dépréciation avec alternative, politique snapshot publiée. (V#1842, V#1884, V#401, PR V#1491, V#744)
20. **Commandes Brigadier natives** avec permissions sur les nœuds (arbre client filtré automatiquement), événement de définition d'arbre par joueur, événement de requête de suggestions avant retransmission, entrée normalisée comme le vanilla, arguments inconnus transportés de façon opaque. (V#416, V#1900, B#2677, B#3042, V#1077, B#3168, V#1045, V#1868)
21. **Types distincts par phase et données client en `Optional`** (locale, réglages, brand, mods) avec événements "reçu/changé" ; jamais de valeur inventée ; interfaces de connexion non implémentables par les plugins. (B#1918, B#3680, V#1110, V#1212, V#1676)
22. **Identité et authentification** : authentification = service enregistrable avec implémentation par défaut déléguable ; identité d'authentification séparée de l'identité persistante ; ce qui est modifiable dans le profil, et quand, est porté par le type ; noms offline validés. (PR V#1590, G#1166, V#273, V#1875, V#1827)
23. **Niveau paquet sanctionné et déclaré** (lecture/écriture typée de paquets ciblés, annonces de canaux, accès lecture seule aux tampons) au lieu de l'injection par réflexion ; les plugins qui l'utilisent sont marqués. (V#594, V#327, PR V#1706, B#3545, B#3519)
24. **Scheduler et contrat de threads** : timer unique + exécuteur par plugin, annulation totale à l'arrêt du plugin, contrat de thread par méthode vérifié en mode développement, détection des appels bloquants et de la réentrance. (W#541, B#2765, B#202, LP#2790, PR V#1010)
25. **Métadonnées de connexion complètes et ping composable** : vhost brut et normalisé, listener, cible résolue, IP réelle après PROXY protocol, version annoncée ; ping modifiable champ par champ, suspendable, avec cache documenté ; listeners multiples modélisés. Fournir aussi un harnais de test pour que les plugins puissent vérifier ces garanties. (V#1162, PR V#1265, V#1624, V#1046, W#443, B#1030)
